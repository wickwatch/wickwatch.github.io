cTrader-cBots in Docker betreiben, mit Dashboard

Die cTrader CLI führt einen cBot ohne die Desktop-App aus, ein Bot passt damit in einen Container auf einem Linux-Server. wickwatch ergänzt, was die Kommandozeile offen lässt: einen Ort, an dem du jeden Bot mit Konto und Log siehst und ihn startest, stoppst und neu konfigurierst.

Was wickwatch mit deinen Bots macht

  • Führt jede Instanz als eigenen Container aus, gestartet über die cTrader CLI, und zeigt Status, Laufzeit, Broker-Verbindung und die letzte Log-Zeile.
  • Legt einen Bot aus einem hochgeladenen Algo an, mit einem Formular aus dessen Parametern oder aus einer vorhandenen .cbotset-Datei.
  • Bewahrt jede gespeicherte Konfiguration als Version auf, die du wiederherstellen kannst, und Parametervorlagen, die einen benannten Satz von Werten auf jede Instanz des Algos anwenden.
  • Verfolgt Positionen, Pending Orders und Deals pro Bot und pro Konto, mit realisiertem P&L, Trefferquote, Profit-Faktor und Risiko pro Trade.
  • Startet Bots nach einem Neustart des Hosts oder von Docker wieder, wenn sie laufen sollten.
  • Stoppt mit einem Notstopp alles auf einem Konto: Bots gestoppt, Orders storniert, Positionen geschlossen. Immer mit Bestätigung, immer im Audit-Log.

Zwei Wege, einen Bot zu definieren

Beide lassen sich auf einem Server mischen.

  • In wickwatch einrichten: Algo hochladen und eine Instanz anlegen. wickwatch erstellt, ersetzt und entfernt ihren Container aus der gespeicherten Konfiguration.
  • Selbst definieren: wickwatch zeigt und steuert jeden Container aus deiner eigenen Compose-Datei, der das Label wickwatch.instance trägt. Solche Container ersetzt oder entfernt es nie.

Was du brauchst

  • Einen Linux-Server mit Docker und Compose. 2 vCPU und 4 GB RAM reichen für das Dashboard und einige Bots.
  • Das Image der cTrader CLI, das du selbst von Spotware beziehst, und eine cTrader ID mit deinen Konten.
  • Deine kompilierten cBots als Algo-Dateien.
  • Einen Reverse Proxy mit HTTPS vor dem Dashboard und ein VPN oder eine IP-Freigabeliste: wickwatch kann Positionen schließen und sollte nicht öffentlich erreichbar sein.

Erst ausprobieren, ohne Broker

Das Image startet mit einem Demo-Adapter: erfundene Konten, Instanzen, Positionen und Logs.

docker run --rm -p 3000:3000 \
  -e MASTER_KEY="$(openssl rand -base64 32)" \
  -v wickwatch-data:/app/data \
  ghcr.io/wickwatch/wickwatch:0.7.0

Für echte Bots folgst du der Installationsanleitung Schritt für Schritt (englisch); die Compose-Dateien für nginx-proxy, Traefik oder einen eigenen Port stehen in den Deployment-Beispielen. Docker wird nur über einen docker-socket-proxy erreicht, der die wenigen API-Aufrufe erlaubt, die wickwatch braucht.
